# domains(全国諸藩 藩主データ)

江戸時代の全国の藩の藩主について、**家系図**と**年代スライダー付きの地図**を表示する静的サイトです。
東北版の [touhoku-domains](https://github.com/Karintou83/touhoku-domains) を全国に広げたものです。
データは Wikidata(CC0)から Python で取得して JSON にし、サイトはその JSON を読むだけです。サーバー側の処理やビルド工程はありません。

## ページ

| ページ | 内容 |
|---|---|
| `index.html` | トップ。地方別の収録数の表(`meta.json` の `by_region`)から、各地方の地図・系図へ |
| `tree.html` | 藩別の家系図。藩(地方ごとに分類、旧国つき)を選び、歴代藩主と、その実父を何世代かさかのぼって表示する(Cytoscape.js + dagre) |
| `all.html` | 全体の系図。実父子の線でつながった一族を「島」とし、代表者(島の中で実父子の線をたどった子孫が最も多い藩主。同点なら世代が上の人)のアイコンで並べる。アイコンの面積は島の人数に比例。島をクリックすると、その島の全員を家系図で描く。地方で一覧を絞れる |
| `map.html` | 地図。年を動かすと、その年に各藩を治めていた藩主と氏を、藩庁の位置に表示する(Leaflet + 国土地理院タイル)。地方で絞り込める。肖像のマーカーは拡大率 7 以上で出す(全国を見渡す縮尺では重なって読めないため) |
| `credits.html` | 表示している肖像の作者・ライセンス一覧 |

`tree.html?domain=<藩のQID>&lord=<人物のQID>`、`all.html?region=<地方名>` / `?island=<島の代表者のQID>` / `?lord=<人物のQID>`、`map.html?region=<地方名>` / `?domain=<藩のQID>` / `?lord=<人物のQID>` / `?year=<年>` で、表示する対象を URL から指定できます(地方名は `config.json` の `regions` の表記。例: `?region=九州`)。`all.html?lord=` は、その人の島を開いてその人に寄せます。

## データを作り直す

Python 3.9 以降。標準ライブラリだけで動きます(追加のインストールは不要)。

```
python scripts/build_data.py            # 足りない生データだけ Wikidata から取得 → data/*.json を生成
python scripts/build_data.py --offline  # 取得せず、data/raw/ にある分だけで生成
python scripts/validate.py              # 生成した JSON の整合性チェック(参照切れ・循環・座標の範囲など)
```

- 取得した生データは `data/raw/` に保存され、**取得済みの分は再取得しません**(Wikidata への問い合わせを増やさないため)。`data/raw/` は git に含めません。
  - 藩・役職・在任など全体を1回で取るもの(`positions.json`・`p39.json` など)は、ファイルがあれば使います。Wikidata を編集したあとに反映したいときは、そのファイルを消してから実行します。
  - 人物や藩ごとに取るもの(`family.json`・`ancestors.json`・`adopted_by.json`・`meta.json`・`gender.json`・`images.json`・`commons_meta.json` など)は、**ID(QID・ファイル名)ごとに取得済みかを控えて**います(`{"done": [...], "rows": [...]}`)。在任(`p39.json`)を取り直して藩主が増えても、増えた人の分だけを取得します。特定の人物を取り直したいときは、そのファイルを消します(全員分を取り直します)。
  - touhoku-domains の `family_chunks/` は「人物リストの何番目の塊か」をキーにしていたため、人物が増えると塊がずれて別人の結果を読む問題がありました。全国版では ID をキーにしたので、この問題は起きません。
- Wikimedia は障害対応などで、問い合わせを「1分に1回」に制限することがあります(HTTP 429)。`wdlib.py` は制限を受けたら間隔を65秒に延ばして待ちます(回避はしません)。制限中は、空の状態からの取得に1〜2時間かかります。取得は塊ごとに保存されるので、途中で止めても続きから再開できます。
- Wikidata Query Service への連絡先として、User-Agent には GitHub の URL だけを入れています。

### スクリプト (`scripts/`)

| ファイル | 役割 |
|---|---|
| `build_data.py` | 取得(fetch)と変換(build)。変換はネットワークなしで何度でも再実行できる |
| `validate.py` | `data/*.json` の検査。error があれば終了コード 1 |
| `wdlib.py` | SPARQL・API の呼び出し、リトライ、キャッシュの共通部品 |
| `fetch_kyukoku.py` | 旧国境(CODH「旧国・旧郡境界データセット」)を取得して `data/kyukoku.geojson` を作る。**任意・未実行**(下の「出典・ライセンス」を参照) |
| `survey_nationwide.py` | 全国版にする前の調査(規模・旧国の入り方・祖先込みのサイズ)。サイトの生成には使いません |

### 設定 (`config.json`)

判断が入る部分は、コードではなくここに書いています。

| キー | 内容 |
|---|---|
| `position_class` | 対象にする役職の上位クラス(近世大名 Q24887524)。これを P279 に持つ藩主職が対象 |
| `extra_positions` | 藩主職のほかに在任として取り込む役職。征夷大将軍(Q131767)のうち 1603〜1867 年に始まる在任(徳川将軍15代)を、江戸幕府(Q205662)を藩の代わりにして載せる。代数は開始年の順に数える |
| `province_classes` | 旧国とみなす P31。令制国(Q860290)と北海道の旧国名(Q1541735、渡島国など) |
| `regions` | 地方の並び順(画面の選択欄・トップページの表の順) |
| `province_to_region` | 旧国(QID)→ 名前と地方。表に無い旧国の藩は「地方不明」になり、`warnings.json` に残る |
| `province_overrides` | Wikidata から旧国が決まらない藩、旧国が複数ある藩の旧国(藩の QID → 旧国の QID と根拠)。Wikidata 側に同じ旧国が入ったら警告で知らせる(指定を外せる) |
| `district_to_province` | 郡 → 旧国の対応表。藩の所在地(P131)が郡で、Wikidata から旧国が決まらないときに使う(Wikidata の郡の項目は今の都道府県にしかつながっておらず、旧国にたどれないため)。表に無い郡は警告(`province_district_unlisted`)で知らせる。初期値の7郡は一般的な対応として記入したもので、出典での確認は未了 |
| `seat_overrides` | 地図上の位置を城に固定する藩。御三卿(田安・一橋)と江戸幕府を江戸城(Q865913)に置く |
| `include_adoption` | 養子関係の線を出力するか。`false`(出さない)/ `true`(すべて)/ `"roots"`(実父がデータに無い人に限り、養親からの線を出す)。現在は `"roots"` |
| `ancestor_generations` | 藩主の実父を何世代さかのぼって取得するか。現在は `8`。増やして `build_data.py` を実行すると、足りない世代だけを追加で取得する |
| `ancestor_keep_generations` | 家系図に必ず載せる祖先の世代数(実父=1)。現在は `2`(実父・祖父)。それより上は、ほかの藩主の系統との合流点と、そこから藩主へ下る途中の人だけを載せる。`null` なら間引かない |
| `p1039_roles` | 親族関係(P1039)の値を養親 / 養子 / その他のどれとして扱うかの上書き |
| `branch_domains` | 固有の陣屋を持たない新田藩 → 本藩。地図では本藩の近くに仮置きする |
| `year_range` / `japan_bbox` | `validate.py` が使う、年と座標の想定範囲 |
| `image_license_prefixes` | 表示してよい画像のライセンス名の先頭(Public domain、CC0、CC BY 系) |
| `image_exclude` | 画像を表示しない人物の QID |

## データ構成 (`data/`)

| ファイル | 内容 |
|---|---|
| `domains.json` | 藩。座標(出所 `source` と精度 `precision` 付き)、旧国 `province`(QID と名前)と出所 `province_source`(`wikidata_direct` / `wikidata_p131` / `wikidata_seat` / `config` / `config_district`)、地方 `region`(不明なら `null`)、在任データ上の最初と最後の年 |
| `lords.json` | 人物。主たる藩 `primary_domain`(最も早い在任の藩)、日本語版 Wikipedia の記事名、氏(出所 `clan_source` 付き)、肖像(ファイル名・作者・ライセンス) |
| `tenures.json` | 在任(人物 × 藩 × 開始年・終了年・代数)。地図の年代スライダーの元 |
| `relations.json` | 家系の線。現在は `blood`(実父 → 子)のみ |
| `warnings.json` | Wikidata 上の欠落・食い違い。画面の「要確認」表示の元 |
| `meta.json` | 生成日時、件数、地方別の藩数・藩主数、旧国と氏の出所の内訳、除外した件数 |

## 方針

- **在任**は、人物側の P39(公職)とその修飾子(開始・終了)を正とします。役職側の P1308(在任者)は代数(P1545)を補うために使い、年が食い違うときは警告に残します。年は年単位です。
- **家系の線は実父子が基本**です。P22(父)と、父の項目の P40(子)の両方から拾います。
- **祖先は、つながりに要る分だけ載せます。** 実父は 8 世代(`ancestor_generations`)までたどって取得し、ほかの藩主の系統と合流するかを確かめます。そのうえで、各藩主の実父・祖父(`ancestor_keep_generations`)と、合流点から藩主へ下る途中の人を載せ、どこにも合流しない長い祖先の列は省きます。省いても、藩主どうしのつながり(全体の系図の島)は変わりません。
- **女性は載せません。** P40 は母の項目にも入っているため、性別(P21)を取得して女性を除いています。性別が未入力で、子に別の実父(P22)がいる人物も、実父としては扱いません。
- **養子関係の線は、実父がデータに無い人(家系図の一番上の人)に限って載せます**。養親は両方向から探します: 本人の項目の親族(P1038)と、ほかの項目から「養子」として挙げられているもの(`adopted_by.json`)。データに無い養親は、藩主と同じように実父をさかのぼって取得し、ほかの藩主の系統とつながるかを確かめます(`include_adoption` が `"roots"`)。孤立した系統を養親とつなぐためで、実父子と区別できるよう点線(婿養子は破線)で描きます。実父が分かっている養子には足しません(実父の線で既につながっていて、線が混み合うため)。養子かどうかは、親族(P1038)と関係(P1039)から判定し、P1039 が無く向きが分からないものは描きません。この判定は「養子は実父の氏を継がない」という氏の補完にも使っています。
- **氏(P53)**は、Wikidata にあればそれを使います。無い場合は、名前の先頭が既知の氏と一致すればその氏とし(名前から推定)、それも無ければ実父の氏を継がせます(養子を除く)。推定した氏は `clan_source` で区別し、画面でも「推定」と示します。
- **座標**は、次の順に採ります。新田藩は本藩の近くに仮置きします。どれも無い藩は地図に出さず、地図ページで一覧にします。
  1. 藩の座標(P625)
  2. 本部所在地(P159。城・陣屋)の項目の座標
  3. 本部所在地の文に付いた座標(修飾子 P625)
  4. 本部所在地(城・陣屋)の所在地(P131。市町村など)の座標 … 概略
  5. 首都(P36。市町村)の座標 … 概略
  6. 藩の所在地(P131)の郡・市町村の座標 … 概略。所在地が令制国だけの藩には使いません(国の中心では粗すぎ、同じ国の藩が1点に重なるため)

  概略の位置は、地図で破線の縁にし、どこから取った座標かを藩の詳細に示します。
- **肖像**は、Wikidata の画像(P18)のうち、ライセンスを確認できたものを内容を問わず表示します。画像ファイルは複製せず、Wikimedia Commons のサムネイルを参照します。
- **不確かな点は隠しません。** 欠落や食い違いは `warnings.json` に残し、画面では ⚠ と朱の枠で示します。

## 分かっている限界

- **収録している藩は、Wikidata に藩主の役職(近世大名 Q24887524 の下位クラスで、ラベルが「〇〇藩主」のもの)と在任(P39)が入っている藩だけです。** 江戸時代のすべての藩を網羅しているとは限りません。地方ごとの数(冒頭の表)の多い少ないは、藩の実数ではなく Wikidata の整備状況を反映していることがあります。トップページにも同じ注意を載せています。
- **地方不明**の藩は、旧国が決まらなかった藩です(藩の項目に旧国も所在地(P131)も無い、所在地が対応表に無い郡や今の市町村だけ、など)。旧国は、藩の文の値 → 所在地(P131)・一部(P361)をたどる → 本部所在地(P159)の所在地をたどる → `config.json` の郡の対応表(`district_to_province`)の順に探します。`province_overrides` で藩ごとに旧国を指定することもできます。
- 氏が Wikidata(P53)にある人物は一部で、多くは名前からの推定です(冒頭の「氏の出所」)。推定の精度は、氏が分かっている人物で試した一致率で示しています。松平のように同じ名字で家が分かれるものは区別できません。
- 座標の無い藩は地図に出ません(地図ページで一覧にしています)。
- 地図で「在任者データなし」と出る期間には、Wikidata の入力漏れのほかに、その藩が実際に存在しなかった期間(廃藩や幕領の期間)も含まれます。この2つはまだ区別していません。
- 実父が2人以上登録されている人物がいます(Wikidata 側の食い違い。人数は冒頭、内容は `data/warnings.json` の `multiple_fathers`)。画面では「要確認」として出ます。

## 出典・ライセンス

- データ: [Wikidata](https://www.wikidata.org/)(CC0)。人物名・藩名から日本語版 Wikipedia の記事へリンクします。
- 肖像: Wikimedia Commons。作者とライセンスは、人物の詳細と `credits.html` に表示します。
- 地図タイル: 国土地理院(白地図・淡色地図)。地図上と地図ページのフッターに出典を表示します。
- 旧国境: 現在は含めていません。`fetch_kyukoku.py` で取得して重ねる場合は、公開前に配布元( https://geoshape.ex.nii.ac.jp/kg/ )で最新の利用条件を確認してください。クレジットの文言は `map.html` のフッターに用意してあります。
